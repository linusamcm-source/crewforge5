# Agent Rectifier

Reads an agent-validator report, parses every FAIL and WARN finding, applies fixes to the
target agent `.md` file, and produces a before/after rectification report. The goal is to
bring the agent to grade A (all pass, 0-2 warnings). The rectifier does not stop until
grade A is achieved — it runs a self-healing loop with agent-validator until the agent is
production-ready.

## When to use

Also trigger when agent-validator's Step 7 offers to fix issues and the user accepts. Takes a
validation report and the target agent file as input, applies all safe fixes, and produces a
rectification report showing exactly what changed and why. After fixes, automatically invokes
agent-validator for a full re-validation. If the grade is below A, another rectification round
begins. This validate-rectify loop continues until grade A is achieved (0 failures, 0-2
warnings). Part of the agent-validator / agent-rectifier self-healing loop — the rectifier
never asks for user confirmation; it fixes and re-validates automatically.

## Why This Exists

The agent-validator diagnoses problems but doesn't fix them. Asking the user to manually
rewrite frontmatter, restructure instructions, add missing tool declarations, and promote
buried instructions is tedious and error-prone. This skill automates the mechanical repairs
— covering the categories that account for ~80% of "my agent doesn't follow instructions"
complaints: tool declaration mismatches, missing role framing, ambiguous instructions, and
absent completion gates.

## What Makes Agent Fixes Different from Skill Fixes

Agents are single `.md` files, not directories. This constrains and simplifies the repair:
- No directory structure to reorganize (no scripts/, references/, assets/)
- All fixes happen in one file — frontmatter and body
- Tool coherence is the critical unique concern (skills don't declare tools)
- Size budget is tighter (agents load fully into context every invocation)
- Role statement quality directly impacts agent behavior

## Workflow

### Step 0: Identify Inputs

You need two things:
1. **Validation report** — a markdown file generated by agent-validator (in `./docs/agent_reports/`)
2. **Target agent path** — the agent `.md` file that was validated

If the user just ran agent-validator, both are in recent context. Otherwise ask:
- "Which validation report?" (list recent files in `./docs/agent_reports/`)
- "Which agent to fix?" (confirm the path from the report header)

### Step 1: Parse the Validation Report

Read the report and extract every finding into a structured list:

```
For each finding:
  - category: structural | tool_coherence | efficiency | compliance
  - severity: FAIL | WARN
  - check_name: the specific check (e.g., "tools_field", "role_statement", "completion_gate")
  - detail: what's wrong
  - location: line number in the agent file if applicable
  - suggested_fix: from the report's Recommendations section (if present)
```

Sort findings: FAILs first (by category order), then WARNs. Structural issues must be
fixed before tool coherence issues, because frontmatter corrections may change what tool
coherence checks find.

### Step 2: Apply Structural Fixes

These are mechanical — apply without asking. Per-finding recipes (frontmatter, description,
trigger context, `<example>` blocks, name mismatch, sensitive content) — load when the report
has structural findings: [references/fix-catalogs.md](references/fix-catalogs.md)

### Step 3: Apply Tool Coherence Fixes

This is the most impactful agent-specific fix category. Recipes for missing/unused tool
declarations, missing `tools:` field, dangling skill references, and missing `color:` — load
when the report has tool coherence findings: [references/fix-catalogs.md](references/fix-catalogs.md)

### Step 4: Apply Efficiency Fixes

Recipes for oversized agent files, heavy-directive overload, and duplicate instructions —
load when the report has efficiency findings: [references/fix-catalogs.md](references/fix-catalogs.md)

### Step 5: Apply Instruction Compliance Fixes

Recipes for role statements, completion gates, ambiguous/buried/conflicting instructions,
missing rationale, implicit assumptions, and role drift — load when the report has
compliance findings: [references/fix-catalogs.md](references/fix-catalogs.md)

### Step 6: Verify Fixes

After applying all fixes:

1. **Run the structural validation script** to confirm structural issues are resolved:
   ```bash
   bash ${CREWFORGE_ROOT}/skills/agent-validator/scripts/validate_agent.sh <agent-file-path>
   ```

2. **Read the fixed agent file end-to-end** to verify:
   - Frontmatter is valid YAML between `---` delimiters
   - `name`, `description`, `tools`, and `color` are all present
   - Body flows coherently — fixes applied in isolation sometimes create awkward transitions
   - No duplicate sections or contradictions introduced by the fixes
   - Role statement, instructions, and completion gate tell a consistent story

### Step 7: Generate Rectification Report

Write a report to `./docs/agent_reports/agent-rectification-{agent-name}-{date}.md`.
Full report template — load when writing the report:
[references/report-template.md](references/report-template.md)

### Step 8: Self-Healing Loop — Validate, Rectify, Repeat Until Grade A

This step is mandatory and automatic. Do not skip it. Do not ask the user whether to proceed.

After generating the rectification report, immediately invoke the **agent-validator** skill
(`/agent-validator`) on the same target agent for a full re-validation (all phases: structural,
tool coherence, efficiency, instruction compliance). Use the skill's full workflow — do not
shortcut to just the structural script.

1. **Invoke `/agent-validator`** with the target agent path. Let it run its complete workflow
   and produce a new validation report in `./docs/agent_reports/`.

2. **Read the new report's Overall Grade.**

3. **If grade is A** (all pass, 0-2 warnings): the loop is complete.
   - Present the user with a final summary showing:
     - Starting grade (from the original validation report that triggered rectification)
     - Final grade: A
     - Total rounds of rectification performed
     - Total fixes applied across all rounds
   - Stop here. The agent is production-ready.

4. **If grade is below A** (B, C, D, or F): another rectification round is needed.
   - Parse the new validation report (same as Step 1 above)
   - Apply fixes for all remaining FAILs and WARNs (Steps 2-5 above)
   - Generate an updated rectification report (Step 7) — append the round number to the
     filename: `agent-rectification-{name}-{date}-round{N}.md`
   - Return to the top of this step (invoke `/agent-validator` again)

5. **Loop until grade A is achieved.** Each round should make measurable progress; if a
   round produces zero fixes (all remaining issues are deferred/unfixable), escalate to the
   user with a clear explanation of what's left and why it needs human judgment.

**Why this is mandatory:** An agent that scores below A will behave inconsistently — tools
it's told to use won't work, instructions it's given will be ignored, and its role will
drift between invocations. The validator and rectifier exist as a pair — one diagnoses, the
other heals. Running them in a loop until grade A ensures the agent is actually
production-ready, not just "better than before."

The agent-validator is at `${CREWFORGE_ROOT}/skills/agent-validator/` — it handles the full
validation workflow including structural checks, tool coherence, efficiency, and instruction
compliance diagnosis.

### Step 9: Present Final Results

After the loop completes at grade A, show the user:
1. The starting grade and final grade (A)
2. Number of rectification rounds performed
3. Total count of fixes applied across all rounds
4. Any items that were deferred to human judgment (if the loop was escalated)
5. The path to the final validation report confirming grade A
