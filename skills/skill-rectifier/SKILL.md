# Skill Rectifier

Reads a skill-validator report, parses every FAIL and WARN finding, applies fixes to the
target skill, and produces a before/after rectification report. The goal is to bring the
skill to grade A (all pass, 0-2 warnings). The rectifier does not stop until grade A is
achieved — it runs a self-healing loop with skill-validator until the skill is production-ready.

## When to use

Also trigger when the user says "repair the skill issues" or "make this skill pass
validation", or when skill-validator's Step 7 offers to fix issues and the user accepts.
Takes a validation report and the target skill as input, applies all safe fixes, and
produces a rectification report showing exactly what changed and why. The validate-rectify
loop never asks for confirmation — it fixes and re-validates automatically until grade A
(0 failures, 0-2 warnings) is achieved.

## Why This Exists

The skill-validator diagnoses problems but doesn't fix them. Asking the user to manually
apply 10+ fixes across multiple files is tedious and error-prone. This skill automates
the mechanical repairs and rewrites ambiguous instructions — the two categories that
account for ~80% of "agents don't follow my skill" complaints.

## Workflow

### Step 0: Identify Inputs

You need two things:
1. **Validation report** — a markdown file generated by skill-validator (in `./docs/agent_reports/`)
2. **Target skill path** — the skill directory that was validated

If the user just ran skill-validator, both are in recent context. Otherwise, if a live
user is available, ask:
- "Which validation report?" (list recent files in `./docs/agent_reports/`)
- "Which skill to fix?" (confirm the path from the report header)

When running autonomously (e.g., invoked from a forked skill-validator context where no
user can answer), do not ask. Resolve inputs yourself: take the most recent
`skill-validation-*` report in `./docs/agent_reports/` whose header names the target
skill; if none exists, run skill-validator in report-only mode first to produce one.
Record which report you resolved in the rectification report.

### Step 1: Parse the Validation Report

Read the report and extract every finding into a structured list:

```
For each finding:
  - category: structural | functional | efficiency | compliance
  - severity: FAIL | WARN
  - check_name: the specific check (e.g., "description_length", "script_executable")
  - detail: what's wrong
  - location: file path and line number if applicable
  - suggested_fix: from the report's Recommendations section (if present)
```

Sort findings: FAILs first (by category order), then WARNs. This ensures critical
issues are fixed before cosmetic ones, because later fixes sometimes depend on
earlier structural repairs (e.g., you can't fix a script's instructions if the
script file doesn't exist yet).

### Step 2: Apply Structural Fixes

Mechanical repairs — frontmatter, short descriptions, dead references, orphan files,
sensitive files, non-standard directories. Apply without asking.
Full per-category fix catalog: [references/fix-catalog.md](references/fix-catalog.md) —
load it when you start Step 2 and keep it in context through Step 5.

### Step 3: Apply Functional Fixes

Script repairs — executability, shebangs, syntax errors, missing dependencies.
Per-fix details: [references/fix-catalog.md](references/fix-catalog.md).

### Step 4: Apply Efficiency Fixes

Oversized SKILL.md, too many heavy directives, large inline code blocks.
Per-fix details: [references/fix-catalog.md](references/fix-catalog.md).

### Step 5: Apply Instruction Compliance Fixes

The most impactful phase — ambiguous, buried, or conflicting instructions, missing
rationale, scope overload, implicit assumptions, missing output templates.
Per-fix details: [references/fix-catalog.md](references/fix-catalog.md).

### Step 6: Verify Fixes

After applying all fixes:

1. **Run the structural validation script** to confirm structural issues are resolved:
   ```bash
   bash ${CREWFORGE_ROOT}/skills/skill-validator/scripts/validate_structure.sh <skill-path>
   ```

2. **Check scripts still work** — if you modified any scripts, verify syntax:
   ```bash
   python3 -c "import ast; ast.parse(open('<script>').read())"  # Python
   bash -n <script>  # Shell
   ```

3. **Read the fixed SKILL.md end-to-end** to verify it's coherent — fixes applied in isolation sometimes create awkward transitions or duplicate sections

### Step 7: Generate Rectification Report

Write a report to `./docs/agent_reports/skill-rectification-{skill-name}-{date}.md`
(create the directory first: `mkdir -p ./docs/agent_reports`).
Full report template: [references/report-template.md](references/report-template.md) —
load it when you write the report.

### Step 8: Self-Healing Loop — Validate, Rectify, Repeat Until Grade A

This step is mandatory and automatic. Do not skip it. Do not ask the user whether to
proceed. **This skill — not the validator — owns the loop.**

Keep a running tally across rounds: round number, fixes applied this round, and the
report's FAIL and WARN counts. You need it for the progress check and the final summary.

After generating the rectification report, immediately invoke the **skill-validator**
skill (`/skill-validator`) on the same target skill, and state in the invocation that
this is a **"report-only re-validation, round {N}"**. Those words matter: they tell the
validator to stop after producing its report instead of invoking this rectifier again,
which would nest a second loop inside this one. Let it run all phases (structural,
functional, efficiency, instruction compliance) — do not shortcut to just the structural
script. Agent simulation may be skipped in intermediate rounds to save time, but the
final round that confirms grade A must run every phase the original validation ran.

1. **Invoke `/skill-validator`** with the target skill path and the report-only wording
   above. It produces a new validation report in `./docs/agent_reports/`.

2. **Read the new report's Overall Grade and its FAIL/WARN counts.** Add them to the tally.

3. **If grade is A** (all pass, 0-2 warnings): the loop is complete.
   - Present the user with a final summary showing:
     - Starting grade (from the original validation report that triggered rectification)
     - Final grade: A
     - Total rounds of rectification performed
     - Total fixes applied across all rounds
   - Stop here. The skill is production-ready.

4. **If grade is below A** (B, C, D, or F): another rectification round is needed.
   - Parse the new validation report (same as Step 1 above)
   - Apply fixes for all remaining FAILs and WARNs (Steps 2-5 above)
   - Generate an updated rectification report (Step 7) — append the round number to the
     filename: `skill-rectification-{name}-{date}-round{N}.md`
   - Return to the top of this step (invoke `/skill-validator` again)

5. **Exit conditions — the loop must stop on the first of these:**
   - **Grade A reached** (success).
   - **5 rounds completed** without reaching A — escalate: something about the skill
     resists mechanical repair and needs human judgment.
   - **A round applies zero fixes** (all remaining issues are deferred/unfixable) — escalate.
   - **No progress for two consecutive rounds** (FAIL+WARN total did not decrease) —
     escalate. This catches oscillation, where fixing one finding re-creates another.

   Escalation means: stop fixing, and hand the user a clear list of what remains, why
   each item couldn't be auto-fixed, and what round history looked like. When no live
   user is available (autonomous/forked context), put the escalation in the final
   rectification report and summary instead of asking.

**Why this is mandatory:** A skill that scores below A will cause agents to behave
inconsistently. The validator and rectifier exist as a pair — one diagnoses, the other
heals. Running them in a loop until grade A ensures the skill is actually production-ready,
not just "better than before." The exit conditions exist because an unbounded loop that
isn't converging burns tokens without adding safety — escalating with a precise list of
what remains is the productive outcome at that point.

### Step 9: Present Final Results

After the loop completes at grade A, show the user:
1. The starting grade and final grade (A)
2. Number of rectification rounds performed
3. Total count of fixes applied across all rounds
4. Any items that were deferred to human judgment (if the loop was escalated)
5. The path to the final validation report confirming grade A
